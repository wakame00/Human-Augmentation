# 人体改造Mod 現状・合意仕様まとめ

更新日: 2026-07-24

## 1. Modの方向性

- NeoForge 1.21.1向けの人体改造Mod。
- 近未来のサイバー医療と、不気味な解剖・マッドサイエンスを融合する。
- 手術による肉体パーツ交換と、別設備によるDNA解析・遺伝子書き換えを二本柱にする。
- 将来はMekanismの人体原子炉・人体核融合炉アドオンへ接続する。
- 魔法、工業、ダンジョン、Mob追加ModのDNAや改造パーツとの連携を想定する。
- 仮Mod IDは `humanaugmentation`、Javaパッケージは
  `com.wakame.humanaugmentation`。後から変更可能だが、ロードマップ序盤は固定する。

## 2. 実装済み

### 身体データ

- プレイヤーごとの身体状態をAttachmentに保存・同期する。
- 脳、眼、心臓、肺、消化器、血液、筋肉、骨格、脊椎、皮膚、特殊部位を持つ。
- 右腕、左腕、右脚、左脚を独立して管理する。
- 四肢は筋肉・骨・末端（左右の手足）の複数セルで構成する。
- 初期状態では天然部位が入っている。
- 天然部位を取り外して空欄にすると、部位に応じたデバフを受ける。

### 人体改造パーツ

- 人工パーツは本来の部位以外を含め、すべての身体スロットへ装着できる。
- 適正部位では効果100%、誤った部位では現在50%。
- 同じパーツを複数装着した場合、効果は100%、50%、25%、12.5%…と逓減する。
- T1人工心臓: 最大体力増加。
- T1人工肺: 酸素能力増加。
- T1人工眼: 暗視。
- T1強化脊椎: ノックバック耐性。
- T1人工筋肉: 攻撃力増加。
- T1強化骨格: 防御力増加。
- 異なるT1パーツ3種類で再生、6種類で耐性の仮セット効果がある。
- パーツには推奨部位、Tier、容量コスト、代謝コストを持たせている。

### 手術UI

- Minecraftのピクセル感に合わせた手描き風SF医療UI。
- 内臓、胸部組織、右腕、左腕、右脚、左脚を切り替えられる。
- 正面固定のプレイヤー表示、身体スロット、空スロットの薄い部位アイコンを表示する。
- 内臓画面に血管状の接続線を表示する。
- 代謝負荷、安定度、設備Tier、SPを表示する。
- 心電図アニメーションと警告表示を実装済み。
- プレイヤーインベントリとホットバーを見やすく分離している。
- パーツをスロット上へ持ったとき、部位とTierに応じた必要SPをプレビューする。
- 手術台使用中はプレイヤーを台上へ固定し、UIを閉じるか損傷すると退出する。

### DNA

- DNAサンプラーでMobから確率採取できる。
- DNAサンプルの由来MobはData Componentへ保存する。
- Mob名は翻訳済みの表示名を優先し、翻訳がなければ利用可能な名称へフォールバックする。
- JSONの `dna_sources` からMob、採取率、遺伝子候補を読み込む。
- 現在の定義はウーパールーパー、ブレイズ、ニワトリ、エンダーマン、クモ。
- DNAは手術用の身体スロットとして扱わず、独立した遺伝子プロファイルとして実装する。
- DNA書き換えと形質発現は未実装。

### T1設備の試作

- 手術台、医療フレーム、手術アーム、T1燃焼式SP入力ブロックを実装済み。
- 現在の構造判定は、手術台を中心とした平面型の仮3×3構造。
- 東西の手術アーム2個と四隅のフレーム4個でT1として認識する。
- 北側の燃焼式入力ブロックは任意接続。
- 燃焼式入力は、手に持ったかまど燃料を右クリックで消費してSPへ変換する。
- 200燃焼tickを100 SPとして換算し、最大1,000 SPをNBTへ保存する。
- バケツなどのクラフト残余物を返却する。
- SPの消費メソッドはあるが、手術処理にはまだ接続していない。
- 燃焼式入力は水平4方向を持ち、燃料・容器・副産物用の3枠Inventoryを内部に持つ。
- 燃料は即時変換せず、燃焼時間中に2 tickあたり1 SPを生成する。
- 標準ItemHandlerを公開し、自動搬入へ接続できる。

### T2設備の試作

- T2手術台、T2医療フレーム、T2精密手術アームを実装済み。
- 主要部品の最低Tierで設備Tierを判定する。
- T2構成では眼、脊椎、追加の四肢筋肉・骨スロットが解放される。
- T1では主要部位、皮膚、各四肢の筋肉1枠・骨1枠を操作できる。
- T2精密制御モジュールを南側へ1個置くと、手術SPコスト表示を15%軽減する。
- T1合成皮膚は防具強度、T2適応皮膚は防具強度と耐火を与える。
- T2設備は現時点では平面型の仮配置であり、箱型構造への移行は未実装。

### T4/T5身体積層の試作

- 第1層は既存身体データをそのまま使用する。
- T4で第2層、T5で第3層を解禁する。
- 内臓・胸部画面に `I / II / III` の層切り替えを表示する。
- 第2・第3層は天然部位を持たない空の追加層として保存する。
- 第2層の手術SPは1.5倍、代謝負荷は1.25倍。
- 第3層の手術SPは2.5倍、代謝負荷は1.75倍。
- 同じ人工パーツの重複逓減は身体層をまたいで適用する。
- 現在はTier 5扱いのクリエイティブ人体改造端末で全3層を検証できる。
- 四肢も3層に対応し、筋肉・骨・左右の手足を追加層へ装着できる。
- 各部位は第II層で追加1枠、第III層まで含めると第I層より追加2枠、合計3枠になる。
- 第III層だけは通常の積層枠に加え、内臓・胸部・各四肢へ補助改造枠を2枠ずつ追加する。

## 3. 合意済みだが未実装

### T1箱型マルチブロック

- T1を中へ入って手術を受ける箱型設備へ変更する。
- 外形は約5×5、高さ4、内部は約3×3を基準に調整する。
- 手術台、手術アーム、コントローラー、入口、動力入力、フレーム・壁で構成する。
- 上位Tierも無制限に巨大化させず、同程度の外形を高性能部品へ更新する方向。

### 構成確定

- 専用アイテム `surgery_calibrator`（仮名）でコントローラーを右クリックする。
- 必要ブロック、内部空間、入口、各部品の向き、動力入力を検査して構成を確定する。
- 不足箇所はメッセージやハイライトで通知する。
- 確定後に重要ブロックが壊れた場合は設備を停止する。
- 修復後は再キャリブレーションを要求する。
- Shift＋右クリックで構成解除。ただし手術中や患者が内部にいる場合は解除不可。

### T1かまど式発電機

- 水平4方向の向きを持つ。
- 正面を炉口、背面をSP出力、側面を燃料搬入、上面を排熱として扱う。
- 背面が設備側を向いていなければ、構成確定時に接続エラーとする。
- GUIに燃料、容器回収、将来の灰・副産物用の3スロットを持つ。
- 燃焼時間、生成速度、SP蓄積量、接続状態を表示する。
- 標準のアイテム入出力を公開し、ホッパー等の自動搬入・回収へ対応する。
- T1はバニラのかまど燃料を使用し、上位Tierから専用燃料を追加できる。

### 実際の手術処理

- 現在の即時スロット反映を廃止し、「変更予定」を一時保存する。
- 実行ボタンで必要SP、設備Tier、安定度、部位難易度を検証する。
- SP消費と身体変更を、途中状態が残らない一回のトランザクションとして処理する。
- 動力不足でもT1手術を許可する案は残っているが、成功率低下・事故内容・最低成功率は未決定。
- 部位ごとに消費SPを変える。
- 誤った部位への装着は効果低下に加え、手術コストも高くする。

## 4. Tier・設備強化の合意案

### 基本原則

- Tierが上がると、設備そのものの基礎性能が上がる。
- 通常設備は全Tierで固定値の加算性能を持つ。
- 上位Tierほど同じ種類の通常設備が加算する量を大きくする。
- T1には専門パーツ、乗算パーツ、専門ソケットを作らない。
- T2以降でのみ、設備の方向性を決める乗算型の専門パーツを解禁する。

### 専門ソケット上限（仮）

| 設備Tier | 専門パーツ上限 |
|---|---:|
| T1 | 0 |
| T2 | 1 |
| T3 | 2 |
| T4 | 3 |

- 同じ専門パーツは原則1個まで。
- 高出力、生命維持などのカテゴリごとに上限を設定できる。
- 高速手術と超精密手術など、相互排他の組み合わせを設定できる。
- 乗算後に成功率・軽減率などの最終上限と下限を適用し、数値暴走を防ぐ。

### 計算順

```text
Tierによる基礎値
+ 通常設備の固定加算
→ 専門パーツ倍率
→ 最終的な上限・下限
```

- 成功率を直接乗算するより、失敗率を専門パーツで乗算軽減する。
- 手術コスト、手術時間、患者ダメージ、燃料効率、SP出力などは別々の倍率として扱う。

### 設備Tier判定（仮）

- コントローラーだけ交換して上位設備になるのを防ぐ。
- コントローラー、手術台、手術アーム、動力入力、生命維持装置など主要部品の最低Tierを設備Tierとする案。
- 外壁やガラスをすべて交換させるか、一定割合だけ要求するかは未決定。

## 5. DNAとMod連携の将来案

- DNA書き換え設備は手術台と分離し、身体スロットへDNAアイテムを置かない。
- DNAの採取、遠心分離、解析、形質選択、注射による導入という工程を想定する。
- 実在のDNA・遺伝学を下敷きにしつつ、ゲームとして理解できる形へ簡略化する。
- 壁登りなどの効果を、解析済み遺伝子を組み合わせるレシピで作る。
- 設備Tierによって扱えるDNAや特殊DNAを制限する。
- 人体改造とDNA効果が重なる場合は相乗効果を持たせる。
- Create導入時は遠心分離などを回転力で動かせるようにし、便利になる一方で設備工程を増やす設定も可能にする。
- Mekanism、Oritech、AE2、Alex's Caves、Goety、Iron's Spells、
  ProjectE、CC:Tweaked、Create、Ars Nouveau、Blood Magic、
  Ender IO、Draconic Evolution、Mystical Agriculture、Psi、SlashBlade、
  Ice and Fire本家・Community Editionなど、NeoForge 1.21.1で利用可能な本家・非公式移植版との連携を候補とする。

## 6. Mekanismアドオンの将来案

- 人体改造Modを基盤にして、後からMekanismアドオンを作る。
- 体内へ一マス原子炉に近い核分裂炉・核融合炉を埋め込む。
- 燃料をジュース状にして摂取し、毎tick発電して装備へ給電する。
- 死亡時はMekanism原子炉事故に近い爆発・汚染を発生させる案。
- 体内でポロニウムやプルトニウムを生成する案と、冷却機構は未決定。
- DNA、臓器、代謝、冷却、放射線耐性を人体改造Mod側の仕組みと接続する。

## 8. まだ決める必要がある項目

- 箱型T1設備の正確なブロック配置、入口方式、内壁素材。
- コントローラーと手術台を別ブロックにするか。
- 発電機のSP生成速度、燃料効率、容量。
- 無動力手術を許すか、許す場合の最低成功率と事故内容。
- 手術の所要時間と、手術中のキャンセル・死亡・ログアウト処理。
- T1で扱える改造Tierと容量上限。
- 通常設備の種類、個数上限、加算値。
- T2以降の専門パーツ一覧、倍率、カテゴリ、排他関係。
- 設備Tier判定で外壁・ガラスに要求する更新割合。
- DNA設備のTier体系を手術設備と共有するか。
- SPを独自エネルギーのまま扱うか、外部エネルギーから変換するAPIを設けるか。
